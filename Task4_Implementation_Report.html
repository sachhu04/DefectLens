2. PROJECT OVERVIEW

In modern manufacturing, industrial visual inspection is critical for ensuring product quality. Identifying subtle defects manually is error-prone and time-consuming. The DefectLens project addresses this by implementing an industrial visual anomaly detection system. It is designed to identify defects (e.g., scratches, contaminations, structural damage) by learning the visual distribution of "normal" fault-free products, since collecting training data for every possible defect type is practically impossible.

The proposed system employs a Vision Transformer (ViT) backbone integrated with a PatchCore-style memory bank. To resolve the massive computational overhead of standard ViTs on high-resolution industrial images, we propose a Multi-Criteria Token Fusion (MCTF) module. MCTF dynamically fuses redundant background patches while protecting critical fine-grained features, drastically reducing inference latency and FLOPs without sacrificing detection accuracy.

Task 4 Part 1 Focus: This initial implementation phase focuses strictly on the foundational infrastructure: automated dataset acquisition, data preprocessing/loading pipelines, and the structural initialization of the core ViT and MCTF modules. The full scoring logic and evaluation remain for subsequent phases.

3. COMPLETE PROPOSED METHODOLOGY

The complete proposed pipeline operates as follows:

Dataset → Data Preprocessing → [ViT Feature Extraction] → [MCTF Token Reduction] → [FAISS Memory Bank Matching] → [Final Output/Evaluation]

  • Data Preprocessing: Resizing, normalization, and tensor conversion of raw high-resolution images.
  • ViT Feature Extraction: Extracting patch-level feature embeddings from input images.
  • MCTF Token Reduction: Bipartite soft-matching based on similarity, informativeness, and token size to fuse redundant background patches.
  • FAISS Memory Bank: Storing normal feature representations and performing K-Nearest Neighbors (KNN) to compute anomaly scores for test images.
Implemented in Task 4 Part 1: Dataset access, Data Preprocessing (loading, resizing, normalization), initialization of the ViT backbone class, and implementation of the MCTF soft-matching algorithm.
Remaining for later stages: Full integration of MCTF into the ViT layers, FAISS Memory Bank population, Anomaly Scoring (distance computation), heat map generation, full evaluation, and API/Frontend deployment.

import urllib.request

def download_and_extract(url, save_path, extract_path):
    print(f"Downloading from {url}...")
    urllib.request.urlretrieve(url, save_path)
        
    print(f"Extracting {save_path}...")
    with tarfile.open(save_path) as tar:
        tar.extractall(path=extract_path)
        
    os.remove(save_path)

6. DATA PREPROCESSING

Vision Transformers expect standardized, normalized input tensors. Our preprocessing pipeline targets resizing and normalization.

Code Snippet 3 – Preprocessing Transforms (src/data/dataset.py)

import torchvision.transforms as T

def get_transforms(img_size: int = 224):
    transform = T.Compose([
        T.Resize((img_size, img_size), interpolation=T.InterpolationMode.BICUBIC),
        T.ToTensor(),
        T.Normalize(mean=[0.485, 0.456, 0.406], std=[0.229, 0.224, 0.225])
    ])
    return transform, None
  1. Image Resizing: We resize raw high-resolution images to 224x224 (standard ViT resolution) using BICUBIC interpolation to preserve edge details which are critical for anomaly detection.
  2. Normalization: We normalize the tensors using ImageNet means [0.485, 0.456, 0.406] and standard deviations. This aligns the input distribution with the data our pre-trained ViT backbone expects, accelerating convergence.

Observed Result: The output is a highly standardized [3, 224, 224] float tensor ready for patch embedding.

Module: Multi-Criteria Token Fusion (MCTF)

  • Objective: To dynamically merge redundant image patches (tokens) based on similarity, informativeness, and token size, reducing the total token count and computational load.
  • Input: ViT feature tensors [Batch, Num_Tokens, Channels].
  • Processing: Calculates attention-based informativeness and cosine similarity. Performs bipartite soft-matching to fuse the least informative, highly similar tokens.
  • Output: Reduced token tensors and updated token size tracking arrays.
  • Implementation Status: Core logic implemented in PyTorch (src/models/mctf.py).

11. CHALLENGES ENCOUNTERED

During this initial phase, several challenges were identified and addressed:

  • Dataset Organization: The MVTec AD dataset has a complex, nested folder structure containing both images and separate ground truth mask folders. Developing a dynamic PyTorch Dataset class that correctly pairs images with their respective masks (or lack thereof for normal samples) required careful pathway logic in dataset.py.
  • Index Tracking in Fusion: The most complex challenge in implementing MCTF was managing token mappings. When tokens are fused, their indices change. Reconstructing the original spatial locations for the final anomaly heatmap requires tracking a mapping tensor across all layers. Our PyTorch implementation currently addresses this via an old_to_new tensor mapping logic, though it adds slight computational overhead.
